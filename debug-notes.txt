Remote connection fix: the audio path over SmartLink hole punch
===============================================================

This build carries a fix for remote connections to radios that have no
port forwarding set up — the "hole punch" path.

What was happening: the connection itself would succeed (you'd hear the
connect confirmation and the radio would respond to commands), but the
audio and meter data never started flowing. After half a minute or so
the app would give up with "no RX antenna / couldn't get a slice."

What we found: the very first data packets sent while the two ends are
still finding each other can bounce. When one bounced, the networking
layer under JJ Flex quietly shut down the entire audio channel and never
told anyone. The connection looked alive — commands worked — but sound
and meters were gone before they started.

What this build does: a bounce during that early window is now treated
as the normal event it is, and the audio channel keeps trying. The
trace file also narrates the whole story now, so if a remote connect
still misbehaves, the trace will say exactly where it stopped.

What to test
------------

1. Remote connect to a radio over SmartLink (the no-port-forwarding
   path especially).
2. Listen — audio should start within a few seconds of connecting.
3. Check meters and the frequency readout are live.
4. If anything fails, grab the trace file — it now tells the UDP story.
